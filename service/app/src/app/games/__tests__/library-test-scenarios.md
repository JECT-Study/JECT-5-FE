# 라이브러리 E2E 테스트 시나리오

> 🎮 **라이브러리 화면의 E2E 테스트 시나리오 문서**

## 📋 개요

이 문서는 라이브러리 화면의 E2E 테스트 시나리오를 정의합니다. 접근성 가이드라인을 준수하여 작성되었으며, 실제 사용자 행동을 기반으로 한 테스트 케이스들을 포함합니다.

## 🎯 테스트 환경

- **화면**: 라이브러리 (LIBRARY, 화면 번호 301)
- **전제 조건**: 로그인 상태 (일부 테스트)
- **접근성**: 접근성 기반 셀렉터 사용 (getByRole, getByLabel, getByText)

## 📝 테스트 케이스 목록

### 라이브러리 네비게이션 테스트

#### 1.3 게임 미리보기 팝업 기능 확인
- **테스트 절차**:
  1. 게임 카드를 클릭한다
  2. 팝업이 뜬 상태에서 'X' 버튼 또는 팝업 영역 밖을 클릭한다
- **기대 결과**: 
  1. '게임 미리보기' 팝업(POPUP OVERVIEW, 화면 번호 103)이 표시된다 (게임명, 제작자 이름, 총 문제 수, 게임 내 문제 이미지 정상 표시)
  2. '게임 미리보기' 팝업이 닫힌다
- **비고**: 로그인 상태 불필요

#### 1.5 '게임 시작' 버튼 기능 확인
- **테스트 절차**:
  1. 게임 카드를 클릭하여 게임 미리보기 팝업을 띄운다
  2. '게임 시작' 버튼을 클릭한다
- **기대 결과**: '참가자 설정' 화면(GAME_PARTICIPANT, 화면 번호 501)으로 이동한다
- **비고**: 로그인 상태 필요

#### 1.6 '내 게임' 버튼 기능 확인
- **테스트 절차**: '내 게임' 버튼을 클릭한다
- **기대 결과**: 대시보드 화면으로 이동한다
- **비고**: 로그인 상태 필요

#### 1.7 '게임 만들기' 버튼 기능 확인
- **테스트 절차**: '게임 만들기' 버튼을 클릭한다
- **기대 결과**: 게임 만들기 화면으로 이동한다
- **비고**: 로그인 상태 필요

#### 1.8 로그아웃 기능 확인
- **테스트 절차**:
  1. '아바타' 버튼을 클릭한다
  2. '로그아웃' 버튼을 클릭한다
- **기대 결과**: 로그아웃 된다
- **비고**: 로그인 상태 필요

### 라이브러리 화면 테스트

#### 2.1 라이브러리 목록 정렬 확인
- **테스트 절차**: 라이브러리 화면에 진입한다
- **기대 결과**: 게임 목록이 최신 순, 인기순으로 정렬되어 표시된다
- **비고**: 로그인 상태 불필요

#### 2.2 검색 기능 (정확한 제목, 띄어쓰기)
- **테스트 절차**:
  1. 검색창에 '명대사 퀴즈'를 입력 후 엔터를 누른다
  2. 검색창에 '명대사퀴즈'를 입력 후 엔터를 누른다
- **기대 결과**:
  1. '명대사 퀴즈' 1개의 라이브러리가 검색 결과에 표시된다
  2. '명대사 퀴즈' 1개의 라이브러리가 검색 결과에 표시된다
- **비고**: 로그인 상태 불필요

#### 2.3 검색 기능 (검색 결과 없음)
- **테스트 절차**: 검색창에 '레크레이션'을 입력 후 엔터를 누른다
- **기대 결과**: 검색 결과가 나타나지 않는다
- **비고**: 로그인 상태 불필요

#### 2.4 '홈' 버튼 기능 확인
- **테스트 절차**: 라이브러리 화면에서 '홈' 버튼을 클릭한다
- **기대 결과**: '홈(비로그인)' 화면(HOME_GUEST, 화면 번호 101)으로 이동한다
- **비고**: 로그인 상태 불필요

## 🔧 테스트 데이터 요구사항

### 필수 테스트 데이터
- **게임 데이터**: 
  - "명대사 퀴즈" 게임 (띄어쓰기 포함)
  - 다양한 게임들 (최신순, 인기순 정렬 테스트용)
  - 존재하지 않는 게임명 "레크레이션"
- **사용자 데이터**: 테스트용 사용자 계정 (로그인 테스트용)

### 테스트 환경 설정
- **MSW**: API 모킹을 위한 Mock Service Worker 설정
- **인증**: 로컬 스토리지 및 쿠키 기반 인증 모킹
- **데이터**: 테스트용 게임 데이터 준비

## ⚠️ 주의사항

1. **접근성 우선**: 모든 셀렉터는 접근성 기반으로 작성
2. **테스트 격리**: 각 테스트는 독립적으로 실행 가능해야 함
3. **상태 관리**: 테스트 간 상태 공유 금지
4. **에러 처리**: 네트워크 오류, 로딩 실패 등 예외 상황 고려
5. **타임아웃**: 적절한 대기 시간 설정
6. **검색 기능**: 띄어쓰기 처리 로직 확인 필요

## 📊 테스트 커버리지 목표

- **기능 커버리지**: 100% (모든 테스트 케이스 구현)
- **접근성 커버리지**: 키보드 네비게이션, 스크린 리더 지원
- **에러 케이스**: 네트워크 오류, 검색 실패 등
- **크로스 브라우저**: Chrome, Firefox, Safari 지원
- **정렬 기능**: 최신순, 인기순 정렬 정확성 검증
- **검색 기능**: 정확한 검색, 부분 검색, 검색 결과 없음 케이스
